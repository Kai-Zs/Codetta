# 练笔小筑 — 设计文档

## 概述

「练笔小筑」是一个面向班级的 Python 刷题练习应用，数据来源于 622 道题库 Excel。支持 Web、Android APK、Windows 三端运行。

**技术栈：** Vue 3 + Vite（前端），Python FastAPI + SQLite（后端），Capacitor（Android 打包），PWA（Windows）

---

## 架构

```
前端 (Vue 3 SPA)
  ├─ Web        → 直接部署
  ├─ Android    → Capacitor 打包 APK
  └─ Windows    → PWA 安装

后端 (FastAPI)
  ├─ /api/auth/*     登录 & PIN 管理
  ├─ /api/questions/* 题库接口
  ├─ /api/progress/*  进度 & 错题
  └─ /api/judge/*     DeepSeek 判题

数据库: SQLite (单文件)
```

## 数据库设计

### users

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增 |
| student_id | TEXT UNIQUE | 10 位纯数字学号 |
| name | TEXT | 名单内有 → 原名，名单外 → "后四位+同学" |
| pin | TEXT | 4 位数字，null=首次登录待设置 |
| in_roster | INTEGER | 是否在 2544名单.xlsx 中 |
| prog_mode | TEXT | "write" / "review"，编程题模式，默认 null（首次弹窗） |
| sound_on | INTEGER | 声音开关，默认 1 |
| vibrate_on | INTEGER | 震动开关，默认 1 |
| created_at | TEXT | 创建时间 |

### questions

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增 |
| q_number | TEXT | 原题号，如 "1.139" |
| chapter | TEXT | 章节号 |
| type | TEXT | "单选" / "判断" / "填空" / "编程" |
| title | TEXT | 题目标题 |
| content | TEXT | 题干正文，单选题不含选项文本（选项已拆到 options 字段） |
| options | TEXT(JSON) | 单选题选项：`["A. Hello", "B. World", ...]`，其余题型 null |
| answer | TEXT | 标准答案：单选存字母 "A"，判断存 "正确"/"错误"，填空存含 `$` 的原串，编程存完整代码 |
| answer_parts | TEXT(JSON) | 填空题解析后：`["raise", "assert"]`，其他 null |
| template | TEXT | 编程题专用，黑色字体部分（预填到编辑器） |
| answer_code | TEXT | 编程题专用，红色字体部分（给 DeepSeek 比对） |
| note | TEXT | 备注 |
| is_active | INTEGER | 0=已删除（8.33–8.36 无答案），1=正常 |

### progress

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增 |
| user_id | INTEGER FK | 关联 users.id |
| question_id | INTEGER FK | 关联 questions.id |
| answer_status | TEXT | "correct" / "incorrect" / "partial" / "pending" / "timeout" |
| user_answer | TEXT(JSON) | 统一 JSON 数组：`[{"input":"raise","is_correct":true},...]` |
| ai_feedback | TEXT(JSON) | `{"score": 8, "comment": "...", "is_correct": true}` |
| mode | TEXT | "sequential" / "random" |
| prog_submit_type | TEXT | "write" / "review" |
| removed_from_wrong | INTEGER | 0/1，手动移出错题本标记 |
| answered_at | TEXT | 作答时间 |

> (user_id, question_id, answered_at) 联合索引，每次作答 INSERT 新行，查当前进度取最新一条。保留重做历史。

### statistics（后端计算，不建表）

- **正确率** = 总对空数 / 总答空数（编程题按 AI 判分结果；填空题 partial 按全错计入分母，分子不加）
- **总进度** = answer_status 不为 null 的去重题数 / 有效题总数（取每题最新一条记录）
- **错题数** = answer_status IN ("incorrect", "partial") AND removed_from_wrong = 0（取每题最新一条记录）

## 预处理流程

1. **解析 HTML 编程题** — 解析 `编程题抽出来的题库.htm`，按 `<font class="font10">`（color:red）拆分模板（黑色）和答案（红色）
2. **清洗 `$`** — 全字段清洗 Excel 转义残留（`'$'w+'` → `'w+'`、`True$` → `True`、`$-inf` → `-inf` 等）
3. **单选题** — 从题干文本解析 A/B/C/D 选项，拿答案原文匹配选项，存选项字母
4. **填空题** — 先清洗 `$` 残留，再按 `$` 拆分多空，存入 answer_parts
5. **判断题** — 看标题栏颜色（HTML 中 font10=red=错误），结合答案栏"正确"/"错误"校验
6. **删除** — 去掉 8.33–8.36（无答案，is_active=0）
7. **输出** — JSON 文件，作为数据库种子数据；有歧义的标记出来人工处理
8. **名单** — `2544名单.xlsx` 也预处理为 JSON，登录时查表匹配学号→姓名
9. **判断题** — 答案栏"正确"/"错误"即最终答案，标题颜色（HTML 中 font10=red）用于校验一致性

## 用户流程

### 登录

```
输入学号（10 位纯数字）
  → 前端校验格式
  → 后端查 users 表
    ├─ 无记录 → 查名单
    │   ├─ 在名单 → 创建用户，name=原名，in_roster=1
    │   └─ 不在 → 创建用户，name="后四位+同学"，in_roster=0
    ├─ 有记录 & pin 为 null → 跳转设置 PIN 页
    └─ 有记录 & pin 不为 null → 验证 PIN → 进入首页
```

**设置 PIN：** 4 位数字，两次输入一致后保存
**忘记 PIN：** 提示"请联系作者"，隐藏路由 `/admin/reset-pin` 可重置任意用户 PIN

### 编程题

**首次遇到编程题 →** 弹窗让用户选择：
- 「动手写代码」(prog_mode="write")
- 「先看思路，再对比答案」(prog_mode="review")
- 选择后存库，可通过设置修改

**write 模式 — 手机布局：**
```
┌──────────────┐
│   题干区域    │
├──────────────┤
│  代码编辑器   │
│  [重置]      │
└──────────────┘
```
编辑器不被输入法遮挡，通过 keyboard-aware 布局适配。

**write 模式 — 大屏布局：**
```
┌─────────────────────┐
│  题干  │  代码编辑器  │
│        │  [重置]     │
└─────────────────────┘
```
编辑器提供「重置」按钮，恢复到模板代码初始状态。

提交后 → DeepSeek API 判分（同步等待，40s 超时，含加载动画）。
- 成功 → 显示 AI 评分 + 评语 + 标准答案
- 超时 → 用户手动选择「做对了」/「做错了」

**review 模式：**
- 显示题干
- 「我有思路了」按钮
- 点击后展开标准答案，同时弹窗「做对了吗？」，用户标正确/错误，直接记录 answer_status

## DeepSeek 判题 Prompt 设计

```
你是一个 Python 编程题批改助手。请根据以下信息评判用户代码：

【题目描述】
{question_content}

【标准答案】
{answer_code}

【用户代码】
{user_code}

【评判要求】
1. 判断用户代码是否正确（功能等价即可，不需要逐字符一致）
2. 给出 0-10 的评分
3. 给出简短评语（中文，不超过 100 字）
4. 如果代码有错误，指出问题

请严格按以下 JSON 格式输出，不要包含任何其他内容：
{"is_correct": true/false, "score": 0-10, "comment": "评语"}
```

超时时间 40 秒，超时后返回 timeout 状态，前端让用户手动判断。

## 非功能需求

- **学号校验：** 10 位纯数字，前后端均校验
- **PIN：** 4 位数字，bcrypt hash 存储
- **DeepSeek API Key：** 后端环境变量 DEEPSEEK_API_KEY
- **跨设备同步：** 用户数据存后端 SQLite，登录即同步
- **题库答案标注：** 页面底部始终显示「题库答案不一定完全正确，仅供参考」
- **AI 标注：** 所有 AI 输出下方显示「人工智能生成，仅供参考」

## 设计评审补充（2026-05-07）

### DeepSeek JSON 解析容错

大模型可能在 JSON 外包 markdown 代码块。后端解析前：
1. 去 ```json ... ``` 包裹
2. 正则提取第一个 `{...}`
3. json.loads 异常时返回兜底：`{"is_correct": false, "score": 0, "comment": "AI 判分解析失败，请手动判断"}`

### 填空题 answer 入库校验

入库前断言：`answer.count('$') + 1 == len(answer_parts)`
不匹配的标记 `is_active=0`，输出日志人工处理。

### SQLite 并发

启用 WAL 模式 + busy_timeout=5000（写锁等待最多 5 秒）：

```python
PRAGMA journal_mode=WAL;
PRAGMA busy_timeout=5000;
```

### 编程题首次弹窗

- 弹窗被关闭 → 默认选 write 模式，存库
- 关闭后右下角轻提示「可在设置中修改编程题模式」

### 随机 ↔ 顺序切换

- 切换到顺序 → 跳到全局第一道未做题
- 切换到随机 → 按当前筛选条件重新洗牌

### /admin/reset-pin 鉴权

暂不做鉴权，留空鉴权占位，后续补充。
